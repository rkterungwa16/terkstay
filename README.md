# Adire Hotels & Suites — booking demo (React frontend)

A config-driven hotel booking app. The frontend is React (built with Vite);
the backend is a small dependency-free Node server. Every style token and
every piece of hotel content lives in `config.json` — no component hard-codes
its own copy or colors.

## Run it (production build, already built)

```
node server.js
```

Then open http://localhost:3000. The `public/` folder already contains a
built copy of the React app, so this works immediately with no `npm install`.

## Develop the frontend (hot reload)

```
cd frontend
npm install
npm run dev
```

This starts Vite's dev server on http://localhost:5173 and proxies `/api/*`
requests to the Node server, so run `node server.js` in another terminal
first. Edit any component and the browser updates instantly.

## Rebuild for production

```
cd frontend
npm run build
```

This regenerates `public/` (the folder `server.js` serves). Run this after
any frontend change before deploying, or before running `node server.js`
standalone.

## Project layout

```
server.js            Static file server + config API (zero dependencies)
config.json           Every style token and every piece of hotel content
package.json           Root package.json — just `npm start` runs server.js
public/                 Vite's build OUTPUT — regenerated by `npm run build`,
                        do not hand-edit
frontend/               React source
  index.html             Vite entry HTML
  vite.config.js          Dev proxy + build output path (../public)
  src/
    main.jsx               ReactDOM root
    App.jsx                 Top-level orchestrator: owns search/nav state,
                            fetches config, composes every component below
    hooks/
      useConfig.js           Fetches config.json via /api/config; exposes
                             a saveConfig() for PUT-ing edits back
    theme/
      applyTheme.js           Writes config.theme onto CSS custom properties
      applyComponentStyles.js Writes each component's config.components.
                             <name>.style block onto its CSS variables
    utils/
      format.js               naira/date formatting, {template} filling,
                              pluralization — pure functions, no state
      hotelData.js             getHotelRooms() / hotelAvailability() — pure
                              functions computing room stock + pricing from
                              a hotel object + config.roomTypes
    components/
      Header.jsx               Logo + branch nav
      Hero.jsx                 Eyebrow/heading/lede, wraps SearchPanel
      SearchPanel.jsx          Controlled filter form (branch/dates/guests)
      ResultsHeader.jsx        Shared title/meta/back-link, used by both
                              HotelList and RoomList
      HotelList.jsx            Filters hotels by branch+availability, renders
                              a grid of HotelCard
      HotelCard.jsx            One hotel: stars, description, price-from,
                              availability note, "View rooms" button
      RoomList.jsx             One hotel's stocked room types, renders a
                              grid of RoomCard
      RoomCard.jsx             One room type: amenities, capacity, price,
                              rooms-left, "Book room" button
      AmenityIcon.jsx          Icon lookup by name (wifi/power/pool/etc.)
      BookingModal.jsx         Guest-details form + validation + payment
                              method selection; owns its own local form state
      PaymentOptions.jsx       Radio group built from config's
                              paymentMethods list
      BookingSummary.jsx       Pricing breakdown box (subtotal/VAT/service/
                              total) — reused by both the form and the
                              confirmation step
      ConfirmationView.jsx     Post-booking stamp + reference + summary
      Footer.jsx               Chain name, branch list, contact info
      Button.jsx               Shared primary/outline button
```

Every component receives its copy and/or data as **props** — nothing is
imported from a global config module inside a component file. `App.jsx` is
the only place that reads `config` directly; everything below it is a pure
function of its props. That's what makes each piece independently reusable
and testable, and it's also why editing `config.json` changes the rendered
page without touching any component code.

## Editing styles

Each component in `config.json`'s `"components"` block has its own `style`
object, e.g.:

```json
"hotelCard": {
  "style": {
    "background": "var(--white)",
    "border": "#EAE2CC",
    "priceColor": "var(--indigo-deep)"
  }
}
```

`theme/applyComponentStyles.js` translates these into CSS custom properties
(`--hotelcard-bg`, `--hotelcard-border`, `--hotelcard-price`, …) that
`frontend/src/styles.css` reads. Change a value, save, reload — no rebuild
needed if you're running `node server.js` against the already-built
`public/`, since the CSS variables are applied at runtime from the fetched
config, not baked in at build time.

Global theme tokens (colors, fonts, radius, the Adire dot pattern) live in
the top-level `theme` block and cascade into every component as fallbacks.

## Editing hotel information

The `hotels` array is the full inventory — one object per property:

```json
{
  "id": "lag-vi",
  "name": "Adire Victoria Island",
  "city": "Lagos",
  "area": "Victoria Island",
  "state": "Lagos",
  "stars": 5,
  "description": "...",
  "priceFactor": 1.30,
  "availability": { "Standard": 4, "Deluxe": 2, "Executive": 1, "Presidential": 0 }
}
```

- `priceFactor` multiplies each room type's `basePrice` (in `roomTypes`) to
  get that hotel's nightly rate.
- `availability` is rooms-left per room-type `id`. A room type is only ever
  offered by a hotel whose `stars` meets that room type's `minStars` —
  enforced in `utils/hotelData.js`, not per-hotel, so you can't accidentally
  make a 3-star hotel sell a Presidential Suite by editing `availability`
  alone.
- Add a new hotel by adding a new object to the array — branch filters, the
  header nav, and availability search all pick it up automatically, no code
  changes required.

`roomTypes`, `amenities`, and `policies` (VAT rate, service charge,
currency) are also just data — edit them the same way.

## Config API (basic CMS behavior)

- `GET /api/config` — returns the current `config.json`
- `PUT /api/config` — overwrites `config.json` with the JSON body you send

```
curl -X PUT http://localhost:3000/api/config \
  -H "Content-Type: application/json" \
  --data @config.json
```

The React app fetches config on load, so a `PUT` followed by a page refresh
is enough to see the change — no server restart or rebuild required.
